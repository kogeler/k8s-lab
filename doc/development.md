# Development

How the repository is laid out, the conventions its code follows, how it is
tested, and what "done" means for a change.

## Layout

```text
ansible/roles/          host, lxd, bootstrap, clusterctl, capn_identity, management_cluster
ansible/requirements*.yml   direct collections / the exact lock
charts/                 capi-cluster-class, capi-workload-cluster, cni-calico, cni-calico-config, metallb, metallb-config
terraform/modules/      workload_cluster, workload_addons (+ modules/access)
tests/playbooks/        the reference playbooks and their group_vars/all.yml, alt-vars.yml
tests/molecule/         scenarios substrate, bootstrap, e2e-local, gha (CI only); shared prepare
tests/inventory/        the test host
tests/vagrant/debian13/ the test VM
tests/fixtures/         the Terraform roots of lab-default; the external-probe chart
tests/charts/           chart checks run by make check
scripts/                variable-contract check, reference generator, CI diagnostics, docs hook
doc/                    this site: architecture, deploy, runbooks, decisions, generated reference
pyproject.toml, uv.lock the runner's Python tools
.tool-versions          the runner's binaries
```

## Conventions

**Roles.** One house style for all six:

- `tasks/main.yml` dispatches one `include_tasks` per area, each with
  `when: [<role>_enabled, <role>_flow_control_<area>]` and the tags
  `<role-kebab>`, `<role_snake>`, `<role-kebab>-<area>`, `<role_snake>_<area>`.
  Those two toggles are the only on/off inputs.
- Task names `<role-kebab> | <area> | <action>`. Public inputs `<role>_*` in
  `defaults/main.yml`, one comment line each, every one declared in
  `meta/argument_specs.yml` (type, required, description); internal constants
  `_<role>_*` in `vars/main.yml`; registers `_<role>_<area>_<what>`.
- Common variables (`k8s_lab_*`) are read only as defaults of role inputs, with
  no fallback literal; a role never reads another role's variables. Every
  change to them updates [the contract](variable-contract.md) and
  `tests/playbooks/group_vars/all.yml` (`make check` enforces it).
- A value the role needs to work is a literal or a `vars/` constant, not an
  input. A preflight only where a wrong host fact would do damage.
- Native modules first; `command` or `uri` writes only behind a pre-check, with
  honest `changed_when`. Key material and kubeconfigs: `no_log: true`,
  `diff: false`.
- **Every role guards itself**: on a live, pivoted host it decides from the
  state whether it has work to do and never re-creates, restarts or
  re-addresses. Dependencies go in `meta/main.yml`, never in a playbook's
  order.
- README per role, at most 80 lines: purpose, requirements, what it changes,
  re-run behavior, undo, the scenario that tests it. Inputs are in the
  [generated reference](reference/roles.md).

**Charts.** Every Kubernetes object the project creates is in a chart. A value
exists only if a caller sets it or an operator plausibly must; it is in
`values.yaml`, in `values.schema.json` (`additionalProperties: false`) and
read by a template. Values the chart needs to work are in the templates. Bump
`version` on every chart change. Hook and test resources get least-privilege
RBAC and leave nothing behind on success; scripts longer than a few lines live
in `files/`.

**Terraform.** No provider blocks in a module; no variable that only mirrors a
chart default; no upper bounds on providers; secrets `sensitive`. Module
READMEs are generated by `terraform-docs`; plan-mode tests with mocked
providers live in each module's `tests/`.

**Everywhere.** English, American spelling, one-line comments that say why.
Terms: management cluster (`mgmt-1`), workload cluster, bootstrap cluster /
bootstrap instance, runner, host, Gate A, Gate B. No Kubernetes object is
applied as a raw manifest.

## Checks

`make check` (after `make deps`) runs every static and render check; CI runs
the same target on every push and pull request:

| Check | What |
|---|---|
| YAML, Ansible | yamllint; ansible-lint over roles, playbooks and scenarios; syntax check of the reference playbooks |
| Variable contract | `scripts/check_variable_contract.py`: every `k8s_lab_*` variable set, read and described; generated tables current |
| Reference pages | `scripts/gen_reference.py --check`: `doc/reference/` matches the code |
| Terraform | fmt, validate, tflint, `terraform test`, `terraform-docs --output-check` for the three modules; the fixture roots' lock files read-only |
| Helm | `helm lint`, `helm template` → `kubeconform -strict` (Kubernetes 1.37 and the CRD catalog); the class chart's template names; Calico's version in lockstep across its two charts |
| Shell, workflows | shellcheck, actionlint |
| Docs | `scripts/check_docs.py` (every make target, file and variable a page names exists); `mkdocs build --strict` |

## Test harness

The scenarios run against one Debian 13 VM (`tests/vagrant/debian13/`,
Vagrant + libvirt): 12 GiB, 8 vCPUs (`K8SLAB_MEM_MB`, `K8SLAB_VCPUS`), and a
raw 40 GiB pool disk (`K8SLAB_LXD_POOL_GB`) the guest names
`/dev/disk/by-id/virtio-k8slab-lxdpool`. `make
vm-up` starts it and writes the SSH configuration the inventory uses;
`make vm-destroy` removes it and the runner-side state; `make vm-reboot`
reboots it.

| Scenario | Converge | Verify |
|---|---|---|
| `substrate` | `tests/playbooks/substrate.yml` | kernel state, binaries, LXD and every object role `lxd` creates |
| `bootstrap` | the substrate, then `management.yml`'s roles up to the CAPN identity | the bootstrap instance, k3s, the providers at their pins, the identity against LXD |
| `e2e-local` | `tests/playbooks/management.yml`, then the fixture's cluster and add-on roots | clean plans; external reachability of each cluster's VIPs from the host and from a client behind the router; NodePort on `eth1` only; every node's addresses and routes; the pivot and re-run safety; secrets hygiene; a scale up and down; the destroy |
| `gha` | the `e2e-local` converge on a GitHub Actions runner | the `e2e-local` verify — **CI only** |

Every scenario runs `create → prepare → converge → idempotence → verify →
destroy`; the second converge must change nothing. `create` and `destroy` only
record state: the VM lives outside Molecule.

```bash
make test-substrate                         # also test-bootstrap, test-e2e
make test-substrate VARS=alt-vars.yml       # every name, address, port and path changed; on a fresh VM
make -C tests/molecule e2e-local-converge   # one action: <scenario>-<action>
make -C tests/molecule reset                # forget Molecule's state
```

`tests/molecule/shared/prepare.yml` gives the VM what a real host has: a
router on the external network (a veth into `br-ext6`, radvd advertising the
external prefix), a client behind it whose traffic from the external prefix
is accepted only from the external link (as a provider's anti-spoofing
filter would — a node that answers through `eth0` fails the verify), and a
signature-free pool disk.

The `gha` scenario changes the machine it runs on (Docker stopped, swap off, a
loop device for the pool) and refuses to run outside GitHub Actions: `make
test-gha` and every `gha-*` target check `GITHUB_ACTIONS`, every playbook of
the scenario asserts it. Run `make test-e2e` locally; both share converge and
verify.

## CI

| Workflow | Runs |
|---|---|
| `lint.yml` | `make check` on every push and pull request |
| `e2e.yml` | `make test-gha` on pull requests that touch code, tests or tooling, on pushes to `main`, nightly, on demand; on failure `scripts/collect-diagnostics.sh` |
| `pages.yml` | the site and `llms-full.txt` from `doc/` on `main` |

Every job runs on `ubuntu-26.04`; actions are pinned by commit SHA; tools come
from `uv.lock`, `ansible/requirements.lock.yml` and `.tool-versions`.

## Done

A change is done when:

1. `make check` passes on the whole repository;
2. a change to a role ran its scenario with idempotence (`make test-substrate`
   or `make test-bootstrap`); a change to roles, playbooks, charts, modules or
   the harness ran `make test-e2e` on a fresh VM (`make vm-destroy` first) —
   in this workspace, with the recap quoted in the pull request;
3. the docs of what changed say what is true now: role README, the
   [architecture](architecture.md), a runbook if an operation changed, a
   [troubleshooting](troubleshooting.md) recipe for a failure found on the way;
   generated pages regenerated (`scripts/gen_reference.py`,
   `scripts/check_variable_contract.py --write`, `terraform-docs`);
4. `CHANGELOG.md` has an entry under `## [Unreleased]` at its top (create
   the heading when it is missing).

## Docs

`doc/` is the site (`make docs` builds it into `.cache/site`; Pages publishes
it with `llms-full.txt`). One fact has one page; the others link to it.
`doc/reference/` and the generated tables of the variable contract are written
by scripts and never edited by hand. Decisions and their reasons are in
[decision records](decisions/README.md).

## Releases

`CHANGELOG.md` is written first. The release pull request renames
`[Unreleased]` to the version and date, so the section is final when it is
merged; a release is tagged only after that merge, and the GitHub release
body is a verbatim copy of the section. Versions follow Semantic Versioning;
tags are `v<major>.<minor>.<patch>` (`v2.0.0`).
